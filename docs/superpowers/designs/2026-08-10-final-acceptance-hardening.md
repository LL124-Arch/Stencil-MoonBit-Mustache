# Stencil 最终验收工程化加固设计

## 目标

在 2026-08-17 最终验收前，把 Stencil 从“核心语法可用、CI 已补齐”的版本提升为“边界清晰、可复现验证、具有真实工程深度”的 MoonBit 开源生态库。所有新增功能都必须有可运行测试、README 用法和变更记录，避免为了增加代码量引入无意义包装。

## 约束

- 保持零外部运行时依赖和 MIT 许可证。
- 保持现有 `render`、`compile`、`Template::render`、部分模板 API 的兼容性。
- GitHub 与 GitLink 使用同一份源码和文档，分别保留创建者本人提交身份。
- CI 继续覆盖格式、严格检查、接口生成、多目标构建和测试；本地没有 C 编译器时只允许明确跳过 native。
- 不宣称完整 Mustache 规范覆盖；README 必须列出支持项和明确不支持项。

## 功能与实现范围

### 1. 扫描与解析可靠性

- 保留无正则扫描器，补充空标签、空白标签、CRLF 输入和特殊 Unicode 的行为定义。
- 保留递归下降 AST 设计，但增加解析深度上限和可诊断的 `TemplateError`，使超深模板失败可控。
- 统一错误消息格式，覆盖未闭合标签、标签错配、意外结束标签和超限输入。
- 增加 Mustache 核心兼容矩阵；对尚未支持的 lambda、动态加载部分模板等能力明确记录为非目标。

### 2. 渲染安全与边界保护

- 保持默认 HTML 转义、三括号和 `&` 原始输出。
- 保持上下文栈、点号路径、列表隐式迭代和反转区块语义。
- 为部分模板嵌套增加最大深度/循环保护，避免恶意或误配置模板导致无界递归。
- 保持缺失变量、缺失部分模板和非法部分源的现有兼容行为，并在 README 中说明；同时在测试中锁定这些行为。
- 覆盖空对象、空数组、空字符串、`false`、`null`、零值、数组中的混合 JSON 类型和对象键遮蔽。

### 3. 可验证的真实基准

- 把基准分为“编译+单次渲染”和“编译一次+重复渲染”两类。
- 使用小型、典型、较大三档模板，覆盖变量、嵌套区块、列表和部分模板。
- 脚本输出迭代次数、模板规模、数据规模、总耗时和平均耗时，并明确区分冷启动/进程启动开销与引擎本体重复渲染。
- 保留一份带主机、工具链、日期和 workload 定义的结果报告，不把单台机器结果写成普适性能承诺。

### 4. 测试与工程规模

- 增加规范行为测试、错误测试、边界/压力测试、部分模板测试和跨目标回归测试。
- 使用确定性生成数据测试不同深度、列表长度、字符串长度和 Unicode 内容，避免依赖随机数导致 CI 不稳定。
- 将有效 MoonBit 代码和测试规模提升到与官方参考范围相匹配的真实工程量，新增代码必须服务于上述功能、测试或工具链。
- 增加测试分类说明和验收报告，使评审者能从 README 直接定位每类证据。

### 5. 文档与开源合规

- README 增加 Mooncakes 链接、版本、完整 API 行为、限制、错误语义、基准复现方法和最终验收命令。
- CHANGELOG 增加 0.1.2 及本轮加固版本记录。
- 修复申报书中的控制字符和过期测试数量，补充当前真实功能、测试和工程数据。
- 验收清单增加源码规模、基准数据、边界测试、唯一贡献者、默认分支、双仓库同步和 Mooncakes 元数据核验项。
- 保持 LICENSE、贡献指南、行为准则和 CI 公开可追踪；新增文件不引入第三方代码或未声明许可证素材。

## 验证与交付顺序

1. 在 GitHub 工作树编写测试并实现功能，保持每个逻辑批次可单独验证。
2. 运行 `moon fmt --check`、`moon check --deny-warn --target all`、多目标 build/info/test 和验收脚本。
3. 运行基准脚本并更新报告，检查结果是否可复现、口径是否诚实。
4. 复核 README、许可证、申报书、CHANGELOG、提交历史和生成接口。
5. 将完全相同的工作树内容同步到 GitLink，分别检查默认分支、远程 HEAD 和唯一贡献者。
6. 仅在本地与 CI 验证通过后，按用户授权提交、推送并更新 Mooncakes 版本；发布前再次检查账号身份和远程目标。

## 非目标

- 不在本轮加入网络运行时、模板文件系统加载、lambda 执行、表达式求值或第三方兼容层。
- 不用重复代码、虚假 benchmark 或自动生成无意义文件来满足代码规模指标。
- 不把 GitHub Actions 的历史失败运行删除；只确保最终提交对应的 CI 为绿色，并在文档中说明验证结果。
